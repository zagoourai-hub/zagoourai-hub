## Twelve-axis contract

1. **User job and decision**: understand who the developer is, what they build, and where to explore next. Evidence: R1. Confidence: medium.
2. **Attention model**: a README-style top bar, technical banner, and split identity hero lead, followed by concise capabilities and project proof. Evidence: R1-R3. Confidence: medium.
3. **Composition**: README bar, hero imagery, identity, short statement, terminal profile snippet, grouped profile facts, stack, selected work, and an AI-assisted workflow. Evidence: R1. Confidence: medium.
4. **Density and spacing**: compact and scannable, short paragraphs, and small two-column groups only for paired facts. Evidence: R1. Confidence: medium.
5. **Typography**: strong title, muted supporting sentence, and monospace only for technology labels and the profile snippet. Evidence: R1. Confidence: medium.
6. **Color roles**: GitHub controls text and surface colors. Supplied images carry the dark technical base and cyan accent. Evidence: R1-R3. Confidence: high.
7. **Surface language**: GitHub-native headings, code spans, and tables. No simulated cards, shadows, custom CSS, or unsupported HTML. Evidence: GitHub Markdown constraint. Confidence: high.
8. **Imagery and data**: use the supplied background and monogram as authentic visual evidence. Do not invent screenshots or metrics. Evidence: R1-R3. Confidence: high.
9. **Navigation and actions**: one README-style bar contains the real profile and repositories links, which are repeated in the hero for discoverability. Direct project links follow in selected work. Evidence: R1. Confidence: medium.
10. **States and motion**: static artifact with descriptive image alt text. No motion or interactive state is possible within a profile README. Confidence: high.
11. **Responsive transformation**: linear content works at every width. The split hero and paired groups contain short content and may scroll safely in GitHub's native table container. Confidence: medium.
12. **Characteristic tells and anti-patterns**: require real assets, no fake stars, activity, availability, social links, or project metrics. Use one cyan visual accent, a truthful terminal snippet, and plain Indonesian-friendly copy. Reject badge overload, emoji UI icons, fake screenshots, and decorative markup. Evidence: R1-R3. Confidence: high.
